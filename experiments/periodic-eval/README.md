# Periodic fixed-panel ASR evaluation

Baseline: reused BF16 vanilla inference from after-100h; never regenerated by
this schedule. Two approved CS/SK gold dialogue fixtures, 688.671 seconds total,
not natural long-session validation. Gold files remain byte-for-byte unchanged.

Number normalization cs-sk-cardinals-v1 supports cardinal integers 0..9999,
standard compounds and explicit case forms. Language is mandatory. Diacritics
are retained: Czech `tri` and Slovak `tři` are errors. Unsupported ordinals,
decimals, leading-zero identifiers and dotted numeric expressions remain
literal. Strict WER remains available; normalized WER uses its own normalized
reference-token denominator. DER uses 250ms collar and scored-time weighting.

Trainer checks policy after each completed distributed update. At 150, 200,
250, ... hours, and the final update, it saves adapter + optimizer + both ranks'
RNG states, publishes a durable request, then exits cleanly. No training data
is skipped. A systemd timer starts the evaluator; one language per GPU, only
fine-tuned inference. TimeoutStartSec=300 bounds wall time across two GPUs.
ExecStopPost records failure or completion, advances the milestone, and resumes
training. Failed evaluations are surfaced and are not silently retried forever.
Inference features and all audio/reference hashes must match the fixed baseline.

A one-time activation service waits for the next normal checkpoint before
restarting the existing Python trainer with the new hook. This avoids rolling
back many already-computed updates. Files are deployed before activation.

Dashboard: http://localhost:8766, combined/CS/SK selector and percentage charts
against actual unique audio hours. W&B uses periodic/* metrics. Saved hypotheses
are rescored on CPU; original outputs are retained. The existing five-minute SSD
checkpoint backup also copies the complete periodic evaluation directory.

Tests: python -m unittest discover -s experiments/periodic-eval -p 'test_*.py'.
Run on mlserver's ASR venv for scoring dependency availability. Nine unit tests
cover language constraints, compounds, conservative handling, milestone
selection, idempotent timeout recovery, and final completion. Desktop/mobile
browser checks verified charts, selectors, table, and no JavaScript errors.
